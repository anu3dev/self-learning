# 01. Knowledge Base vs OpenSearch Serverless Collection

Knowledge Base is the higher-level **RAG knowledge layer**.

```text
Documents
   ↓
Parsing
   ↓
Chunking
   ↓
Embedding
   ↓
Vector storage
   ↓
Retrieval
```

So:

> **Knowledge Base = RAG knowledge layer**

OpenSearch Serverless Collection is the **search/storage infrastructure**.

```text
Collection
   ↓
Vector Index
   ↓
Vector Fields
   ↓
Stored Embeddings
```

So:

> **OpenSearch Collection = Vector search/storage infrastructure**

### Easy analogy

```text
Knowledge Base
=
Librarian + cataloging + search process

OpenSearch Collection
=
Organized storage/search system
```

They are **not competing services**.

```text
                 Bedrock Knowledge Base
                         │
              ┌──────────┴──────────┐
              │                     │
         Ingestion                Retrieval
              │                     │
              ▼                     ▼
        Chunk + Embed        Vector Search
                                    │
                                    ▼
                         OpenSearch Serverless
                              Collection
                                    │
                                    ▼
                              Vector Index
```

# 02. Creating a Knowledge Base — Parsing + Chunking + Vector Store

The Knowledge Base pipeline turns documents into searchable knowledge.

```text
PDF / DOC / TXT / HTML
        ↓
     Parser
        ↓
     Chunks
        ↓
Embedding Model
        ↓
Vector Embeddings
        ↓
Vector Store
```

### Parser

Parser answers:

> **How do I extract meaningful text/data from this document?**

```text
PDF
 ↓
Parser
 ↓
Text
```

Parsing is especially useful for documents containing tables, images, structured content, or complex layouts.

### Chunking

A large document is broken into smaller pieces:

```text
Document
│
├── Chunk 1
├── Chunk 2
├── Chunk 3
├── Chunk 4
└── ...
```

Each chunk can then be embedded:

```text
Chunk 1
 ↓
Embedding Model
 ↓
[0.12, -0.43, 0.77, ...]
```

The vector represents the semantic meaning of the chunk.

# 03. Knowledge Base Configuration — What Do These Fields Mean?

When using OpenSearch Serverless as the vector store, configuration can include:

- Collection ARN
- Vector index name
- Index field mapping
- Text field name
- Bedrock managed metadata field

These tell the Knowledge Base:

> **"Here is the OpenSearch infrastructure where you should store/retrieve my vectors, and here is how my index is structured."**

### Collection ARN

Example:

```text
arn:aws:aoss:us-east-1:123456789012:collection/abc123
```

ARN identifies the OpenSearch Serverless collection.

```text
Collection ARN
=
"Which OpenSearch collection should I use?"
```

### Vector Index Name

Inside the collection, you can have indexes.

```text
OpenSearch Collection
        │
        └── knowledge-base-index
```

The vector index contains searchable records.

```text
Collection
   ↓
Index
   ↓
Documents / vectors
```

### Index Field Mapping

Conceptually:

```text
Vector field
    ↓
embedding

Text field
    ↓
text

Metadata field
    ↓
metadata
```

The Knowledge Base needs to know:

```text
Where is my vector?
Where is my text?
Where is my metadata?
```

### Text Field Name

Example:

```text
text
```

This is the field containing the actual text associated with the vector.

Example:

```json
{
  "text": "Amazon S3 provides object storage...",
  "embedding": [0.12, -0.31, 0.77],
  "metadata": {}
}
```

### Bedrock Managed Metadata

Metadata provides additional information about the chunk.

```text
chunk:
"Amazon S3 provides object storage..."

metadata:
{
  "source": "s3-user-guide.pdf",
  "page": 15,
  "document_type": "AWS Documentation"
}
```

Metadata can help retrieval/filtering and preserve information about where the chunk came from.

# 04. What Is Amazon SageMaker AI?

Amazon SageMaker AI is AWS's managed platform for building, training, deploying, and operating machine-learning models.

Think:

```text
Bedrock
=
Use foundation models easily

SageMaker AI
=
Build / train / customize / deploy ML models
```

Simplified comparison:

| Bedrock | SageMaker AI |
|---|---|
| Generative AI platform | ML platform |
| Use foundation models | Build/train/use ML models |
| Model inference | Training + inference |
| RAG | ML experimentation |
| Agents | Model development |
| Easier for application developers | More ML/data-science oriented |

# 06. What Is Amazon Personalize?

Amazon Personalize is an AWS managed machine-learning service designed to create **personalized recommendations**.

Think:

```text
Netflix
Amazon
Spotify
YouTube
```

A recommendation system determines:

> **"What is this particular user likely to be interested in?"**

### Your Use Case

Use Amazon Personalize and Amazon Bedrock to generate personalized marketing emails suggesting three streaming movies.

There are two different AI jobs.

### Amazon Personalize

Determines:

```text
Which 3 movies should we recommend?
```

```text
User
 ↓
Personalize
 ↓
Movie A
Movie B
Movie C
```

### Amazon Bedrock

Generates the human-friendly email.

```text
Movie A
Movie B
Movie C
     ↓
   Bedrock
     ↓
"Hi,
Based on your interests, you might enjoy..."
```

Therefore:

```text
Personalize
=
Recommendation brain

Bedrock
=
Generative AI / language brain
```

This is an example of combining specialized AI services.

# 07. What Is a Notebook in SageMaker AI?

A notebook is an **interactive coding environment** where you can write and execute code step by step.

Most commonly you will encounter Jupyter notebooks.

Think:

```text
Notebook
=
Code + Output + Explanation
```

Example:

```python
# Load data
data = ...

# Explore data
data.head()

# Train model
model.fit(data)

# Test model
model.predict(...)
```

Instead of running an entire `.py` application, you can execute individual cells.

### Why are notebooks popular in AI/ML?

ML work is often experimental.

```text
Load data
   ↓
Inspect data
   ↓
Change something
   ↓
Run
   ↓
See result
   ↓
Change again
   ↓
Run again
```

For you:

> A SageMaker notebook is basically an **interactive development/testing workspace for ML and AI code**.

# 08. What Is Amazon Elastic Container Registry (ECR)?

ECR = **Amazon Elastic Container Registry**.

It is AWS's managed **Docker/container image registry**.

Think:

```text
Docker Image
     ↓
     ECR
     ↓
ECS / EKS / Lambda / SageMaker
```

### What Is a Container Image?

You can package an application and its dependencies into a Docker image.

Example:

```text
my-ai-agent:v1
```

Push it to ECR:

```text
Docker
   ↓
docker push
   ↓
ECR
```

Then another AWS service can pull that image.

```text

```

Build a Docker image:

```text
Dockerfile
   ↓

   ↓
ECR
```

Then SageMaker can use that container image for supported workloads.

Conceptually:

```text
Your Code
   +
Libraries
   +
Runtime
   ↓
Docker Image
   ↓
ECR
   ↓
SageMaker
```

# 10. ECR Is NOT a Container Runtime

Very important:

> **ECR stores container images. It does not primarily run your container.**

Think:

```text
ECR
=
Docker image warehouse
```

Runtime services include:

```text
ECS
EKS
AWS Fargate
```

Other AWS services can consume container images for supported workloads.

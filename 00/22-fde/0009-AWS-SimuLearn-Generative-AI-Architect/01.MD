# 1. Temperature

## What is Temperature?

Temperature controls the **randomness / creativity** of an LLM response.

| Temperature | Behavior | Best For |
|---|---|---|
| Low / close to `0` | Focused, deterministic | Technical and factual tasks |
| Medium | Balanced | General conversations |
| High / close to `1` | More varied and creative | Creative writing and brainstorming |

### Easy Memory

```text
LOW temperature  → predictable
HIGH temperature → creative / varied
```

# 2. AgentCore — Big Picture

Amazon Bedrock AgentCore provides infrastructure for building and running AI agents.

An Agent can:

- Understand the user's request
- Decide what information it needs
- Retrieve information from a Knowledge Base
- Call tools
- Access backend capabilities through Gateway
- Generate a final natural-language response

## Important Concept

An Agent is **not just an API**.

A traditional API might do:

```text
GET /products
```

An Agent can decide:

```text
User request
      ↓
Understand intent
      ↓
What information is needed?
      ↓
Knowledge Base?
      ↓
Tool?
      ↓
Backend data?
      ↓
Generate answer
```

The Agent decides **what it needs to do**.

# 3. AgentCore Runtime

## What is AgentCore Runtime?

AgentCore Runtime is where your deployed AI Agent runs.

Think:

```text
AgentCore Runtime
        ↓
    Runs Agent
        ↓
Agent understands request
        ↓
Agent decides what to do
```

Your Node.js or Java application can invoke the deployed AgentCore Runtime.

## Runtime Invocation

AWS provides the `InvokeAgentRuntime` API.

Conceptually:

```text
Node.js / Java
      │
      │ InvokeAgentRuntime
      │
      │ Runtime ARN + user message
      ▼
AgentCore Runtime
      │
      ▼
     Agent
```

The response can be streamed back to the application.

# 4. AgentCore Gateway

## What is Gateway?

AgentCore Gateway is a **tool access / mediation layer**.

The Agent uses Gateway when it needs access to external tools or backend capabilities exposed through that Gateway.

### Important

Gateway:

- Does not need to know your database password
- Does not directly become your database
- Routes tool requests to configured targets

The basic flow is:

```text
Agent
  ↓
AgentCore Gateway
  ↓
Target
  ↓
Lambda
  ↓
Backend system
```

---

# 5. Gateway Target

## What is a Target?

A Target tells Gateway:

> When this tool/capability is requested, where should the request go?

Example:

```text
AgentCore Gateway
       │
       └── Target
             │
             └── cs_product_lambda
```

Suppose the tool is:

```text
check_inventory
```

Input:

```json
{
  "product_id": "PEGASUS-2026",
  "size": 10
}
```

Gateway maps this tool capability to the configured Lambda target.

```text
check_inventory
      ↓
Gateway
      ↓
Target
      ↓
cs_product_lambda
```

# 6. Gateway → Lambda → Secrets Manager → RDS

This is one of the most important flows to remember.

## Complete Flow

```text
Agent
  ↓
AgentCore Gateway
  ↓
Gateway Target
  ↓
Lambda
  ↓
Secrets Manager
  ↓
RDS
```

The response travels back through the same layers:

```text
RDS
 ↓
Lambda
 ↓
Gateway
 ↓
Agent
```

## Step 1 — Agent Calls Tool

Suppose the user asks:

> Where is my order 12345?

The Agent decides:

```text
I need order information.

Available tool:
get_order_details
```

Tool input:

```json
{
  "order_id": "12345"
}
```

## Step 2 — Agent Calls Gateway

```text
Agent
  ↓
Gateway
```

Gateway knows:

```text
get_order_details
        ↓
      Target
        ↓
cs_bot_lambda_diy
```

This relationship was configured when the target was created.

## Step 3 — Gateway Invokes Lambda

Lambda receives:

```json
{
  "order_id": "12345"
}
```

## Step 4 — Lambda Gets Database Credentials

Lambda should **NOT** contain credentials like:

```text
username = "admin"
password = "mypassword123"
```

Instead Lambda knows the ARN of the secret.

Example:

```text
DB_SECRET_ARN=
arn:aws:secretsmanager:us-east-1:123456:secret:rds-secret
```

Lambda calls:

```text
Lambda
   ↓
Secrets Manager
```

Secrets Manager returns:

```json
{
  "username": "dbuser",
  "password": "********",
  "host": "mydb.xxxxx.rds.amazonaws.com",
  "port": 3306
}
```

### Critical Security Point

```text
Agent           ❌ does NOT receive DB credentials
Gateway         ❌ does NOT need DB credentials
Lambda          ✅ receives credentials
Secrets Manager ✅ stores credentials
```

## Step 5 — Lambda Queries RDS

Lambda connects to RDS and executes something like:

```sql
SELECT order_id, status, delivery_date
FROM orders
WHERE order_id = '12345';
```

RDS returns:

```json
{
  "order_id": "12345",
  "status": "SHIPPED",
  "delivery_date": "2026-09-06"
}
```

## Step 6 — Result Returns to Agent

```text
RDS
 ↓
Lambda
 ↓
Gateway
 ↓
Agent
```

The Agent receives business data, not the database credentials.

## Step 7 — Agent Generates Human Response

Agent knows:

```text
Order: 12345
Status: SHIPPED
Delivery: September 6
```

It generates:

> Your order 12345 has shipped and is expected to arrive on September 6.

Example:


```text

❌ IAM permissions
❌ Gateway details
```

# 12. Invoking AgentCore Runtime from Node.js

Node.js uses the AWS SDK.

Install:

```bash
npm install @aws-sdk/client-bedrock-agentcore
```

Example:

```javascript
import {
  BedrockAgentCoreClient,
  InvokeAgentRuntimeCommand
} from "@aws-sdk/client-bedrock-agentcore";

import crypto from "crypto";

const client = new BedrockAgentCoreClient({
  region: process.env.AWS_REGION
});

const agentRuntimeArn =
  process.env.AGENTCORE_RUNTIME_ARN;

export async function askAgent(userMessage) {

  const sessionId = crypto.randomUUID();

  const payload = JSON.stringify({
    prompt: userMessage
  });

  const command = new InvokeAgentRuntimeCommand({
    agentRuntimeArn,
    runtimeSessionId: sessionId,
    payload: Buffer.from(payload),
    qualifier: "DEFAULT"
  });

  const response = await client.send(command);

  const chunks = [];

  for await (const chunk of response.response) {
    chunks.push(
      Buffer.from(chunk).toString("utf-8")
    );
  }

  return chunks.join("");
}
```

```javascript
import express from "express";
import { askAgent } from "./agent.js";

const app = express();
```

# 19. Knowledge Base vs Gateway

This distinction is extremely important.

| Requirement | Use |
|---|---|
| Product documentation | Knowledge Base |
| Return policy | Knowledge Base |
| Shipping policy | Knowledge Base |
| Size guide | Knowledge Base |
| Product descriptions | Knowledge Base |
| Current inventory | Gateway → Tool |
| Current order status | Gateway → Tool |
| Cancel order | Gateway → Tool |
| Create order | Gateway → Tool |
| Update customer data | Gateway → Tool |

### Easy Memory

```text
Knowledge Base = KNOWLEDGE

Gateway = TOOL / ACTION ACCESS
```

# 23. Route 53 vs API Gateway vs ALB

### Question it answers:

> WHERE should this domain go?

Example:

```text

       ↓
AWS infrastructure
```

```text

```

---

## API Gateway

### Question it answers:

> WHICH API should handle this request?

Example:

```text
POST /api/chat
       ↓
API Gateway
       ↓
Backend
```

Common responsibilities:

- API routing
- Authentication / authorization
- Throttling
- Request handling
- API management

Think:

```text
API Gateway = API Front Door
```

---

## ALB

### Question it answers:

> WHICH healthy backend server/container should receive this request?

Example:

```text
ALB
 ├── Node container 1
 ├── Node container 2
 └── Node container 3
```

Think:

```text
ALB = Load Balancer
```

# 26. Security Boundaries

A very important principle:

## Browser should know only what it needs.

React should NOT contain:

```text
❌ AWS access keys
❌ DB username
❌ DB password
❌ RDS endpoint
❌ Secrets Manager secret
❌ Lambda credentials
❌ Internal Gateway configuration
```

## Backend

Node.js / Java can know:

```text
AgentCore Runtime ARN
AWS Region
```

and use its IAM role to invoke AgentCore.

## Lambda

Lambda can know:

```text
Secret ARN
```

and use IAM permission to retrieve the actual credentials.

## Secrets Manager

Stores:

```text
DB username
DB password
DB host
DB port
```

## RDS

Stores:

```text
Orders
Products
Inventory
Customers
```

# 36. Final Interview Answer

If an interviewer asks:

> How would you integrate an AI Agent with an existing Node.js application and database?

A strong answer:

```text
The React frontend sends the user's request to our Node.js backend.

The Node.js backend invokes the deployed Amazon Bedrock AgentCore
Runtime using InvokeAgentRuntime and the Runtime ARN.

The Agent analyzes the request and decides whether it needs knowledge
from a Bedrock Knowledge Base or needs to invoke a backend tool through
AgentCore Gateway.

For knowledge-based questions, the Agent retrieves relevant
information from the Knowledge Base using RAG.

For live transactional data such as inventory or order status,
the Agent invokes a tool exposed through AgentCore Gateway.

The Gateway routes the request to the configured target, such as
a Lambda function.

The Lambda retrieves database credentials from AWS Secrets Manager,
queries RDS, and returns only the required business data.

The Agent uses that result to generate the final response, which
flows back through AgentCore Runtime to Node.js and finally to
the React frontend.

Database credentials never need to be exposed to the Agent or
frontend.
```

Prompt injection is a security concern particularly relevant to Generative AI applications.

An attacker attempts to manipulate the AI system through specially crafted inputs/prompts.

```text id="n6o5lm"
Attacker
   ↓
Malicious Prompt
   ↓
GenAI Application
   ↓
Attempt to bypass controls
```

# 6. AWS Shared Responsibility Model ⭐⭐⭐⭐⭐

AWS security follows the **Shared Responsibility Model**.

```text id="v8x1f3"
AWS
→ Security OF the Cloud

Customer
→ Security IN the Cloud
```

## AWS Responsibility

AWS secures the underlying cloud infrastructure, including:

* Data centers
* Physical infrastructure
* Regions
* Physical servers

---

## Customer Responsibility

Customers are responsible for securely configuring and using AWS services.

Examples:

* Access control
* Encryption
* Firewall/security configuration
* Network traffic
* Data protection

### Easy way to remember

> **AWS secures the cloud. You secure what you put in the cloud.**

# 7. AWS IAM ⭐⭐⭐⭐⭐

IAM = **Identity and Access Management**

It controls:

> **Who can access what, and what they can do.**

IAM policies are JSON documents that can:

* Allow actions
* Deny actions

Example concept:

```text id="k2q5fr"
User / Role
     ↓
IAM Policy
     ↓
AWS Resource
     ↓
Allow / Deny Action
```

---

# 8. Principle of Least Privilege ⭐⭐⭐⭐⭐

Grant only the permissions required to perform a task.

Example:

A developer needs permission to deploy a model to a SageMaker endpoint.

Give:

```text id="3d9c3k"
Deploy Model
```

Don't automatically give:

```text id="c6j2xq"
Delete Model
Access unrelated data
Delete S3 data
```

### Remember

> **Minimum permissions required → minimum security exposure.**

The transcript specifically recommends least privilege as an IAM best practice.

---

# 9. IAM Roles ⭐⭐⭐⭐⭐

An IAM Role is an identity that can be **assumed by a person or AWS service**.

Example:

```text id="j6y0t5"
EC2
 ↓
Assume IAM Role
 ↓
Temporary Credentials
 ↓
Access S3
```

Instead of storing permanent access keys inside the EC2 instance.

### Why roles?

They provide:

* Temporary credentials
* Limited permissions
* Reduced exposure of long-lived credentials

---

## Example — EC2 → S3

```text id="8c9g1p"
EC2 Instance
     ↓
Assume IAM Role
     ↓
Temporary Credentials
     ↓
S3
```

Suppose the role allows:

```text id="v4x2o6"
PUT / UPDATE
```

but does not allow:

```text id="q0x7yz"
DELETE
```

The EC2 application can update data without receiving permanent credentials.

* IAM policies
* KMS key policies

```text id="w3t6z9"

      +
Encryption Key
      ↓

```

---

# 12. KMS + IAM Protection

The transcript gives an important example.

Suppose someone accidentally gets permission to read an S3 bucket.

If the S3 data is encrypted with a KMS key, they also need permission to use that key to decrypt the data.

```text id="k7g2q1"
S3 Read Permission
       +
KMS Key Permission
       ↓
Can decrypt data
```

Without KMS key permission, reading the encrypted data isn't enough to access its contents.

Some AWS services such as S3 and SageMaker support default encryption, while customers can also specify their own keys.

# 28. Generative AI Security Scoping Metrics ⭐⭐⭐⭐⭐

The transcript introduces a mental model called **Generative AI Security Scoping Metrics**.

Core idea:

> **The more control and customization you have over an AI system, the more security responsibility you have.**

```text id="z2p5q8"
Less Control
    ↓
Less Responsibility

More Control
    ↓
More Responsibility
```

The transcript describes scopes from **Scope 1 → Scope 5**.

---

# 29. Scope 1 — Consumer Application

Example:

```text id="w7r3m9"
Consumer GenAI Application
        ↓
You consume the service
```

Characteristics:

* Ready-made application
* You don't control the underlying model
* You don't control its training data
* You cannot modify the model

Therefore, your security responsibility is relatively lower.

You are still responsible for **using the application appropriately**.

---

# 30. Scope 2 — Enterprise Application

Enterprise employees use an external AI application.

Now organizations need to consider:

* What data employees are allowed to provide
* Data classification
* Data flow
* Data residency
* Appropriate usage

```text id="u6k1p3"
Enterprise
    ↓
External AI Application
    ↓
Employee Data
```

The organization has more responsibility than a consumer simply using a ready-made application.

---

# 31. Scope 5 — Build/Train From Scratch

Scope 5 represents organizations that have maximum control over the model.

```text id="x8n2v4"
Own Data
   ↓
Own Training
   ↓
Own Model
   ↓
Own Infrastructure / Controls
```

These organizations are responsible for practically every aspect, including:

* Data controls
* PII protection
* Risk management
* Model security
* Model governance

### Key concept

```text id="m7q3y5"
Scope 1
→ Least control / lower responsibility

        ↓

Scope 5
→ Maximum control / highest responsibility
```

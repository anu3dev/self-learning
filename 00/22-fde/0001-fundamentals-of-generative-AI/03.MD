# Amazon Bedrock — Foundation Model Customization & Features

## 1. Ways to Customize a Foundation Model

There are several approaches, depending on **complexity, time, compute, cost, and how much you want to change the model**.

```text
Foundation Model
      │
      ├── Prompt Engineering
      │
      ├── RAG
      │
      ├── Fine-Tuning
      │
      ├── Continued Pre-Training
      │
      └── Train From Scratch
```

### Quick Comparison

| Approach               | Changes Model?    | Data Required            | Main Purpose                          |
| ---------------------- | ----------------- | ------------------------ | ------------------------------------- |
| Prompt Engineering     | ❌ No              | Prompt/examples          | Influence behavior                    |
| RAG                    | ❌ No              | External knowledge       | Provide current/private information   |
| Fine-Tuning            | ✅ Yes             | Labeled data             | Adapt model to a specific task/domain |
| Continued Pre-training | ✅ Yes             | Large unlabeled dataset  | Teach additional domain knowledge     |
| Train from scratch     | ✅ Build new model | Massive data + resources | Create a foundation model             |

---

# 2. Prompt Engineering ⭐⭐⭐⭐⭐

**Prompt engineering** means refining the prompt to get a better response from the foundation model **without changing the model itself**.

```text
User Prompt
     ↓
Foundation Model
     ↓
Better / More Relevant Response
```

It is also referred to in the transcript as **in-context learning**.

### Why use it?

* Easy to implement
* No model retraining
* No model-weight changes
* Can provide domain-specific context
* Can improve response quality

---

# 3. Zero-Shot Prompting

No examples are provided.

```text
Instruction
     ↓
LLM
     ↓
Response
```

Example:

```text
"Create a bulleted list of tasks
needed to prepare a presentation."
```

The model relies on its existing knowledge and capabilities.

### Remember

> **Zero-shot = 0 examples**

---

# 4. One-Shot Prompting

Provide **one example** to guide the model.

```text
Instruction
    +
One Example
    ↓
LLM
    ↓
Response
```

The example demonstrates the desired:

* Style
* Structure
* Format

The underlying model is **not changed**.

### Remember

> **One-shot = 1 example**

---

# 5. Few-Shot Prompting

Provide **multiple examples** in the prompt.

```text
Instruction
    +
Example 1
Example 2
Example 3
    ↓
LLM
    ↓
Response
```

The examples guide the model toward the desired output style and structure.

Again:

> **No model retraining is required.**

---

# 6. Chain-of-Thought Prompting

Used for problems requiring reasoning.

Instead of simply asking for the answer, the prompt asks the model to work through the problem **step by step**.

```text
Complex Problem
      ↓
Step 1
      ↓
Step 2
      ↓
Step 3
      ↓
Final Answer
```

The transcript explains that breaking a complex problem into smaller steps can help the model approach the problem systematically.

---

# 7. Negative Prompting

Negative prompting tells the model what **should not appear** in the output.

Example:

```text
Generate a joke
+
Do NOT reference women
```

Useful when you want to explicitly exclude:

* Certain topics
* Words
* Elements
* Unwanted content

---

# 8. Prompt Templates ⭐⭐⭐⭐

Application developers shouldn't rely on every user to create a perfect prompt.

Instead, developers can create a **prompt template**.

Example:

```text
Template:

Create a {length} {content_type}
about {topic}
using a {tone} tone.
Avoid bias.
```

Then users provide variables:

```text
length       → short
content_type → blog
topic        → water conservation
tone         → professional
```

### Benefits

Prompt templates can define:

* Output length
* Tone
* Context
* Persona
* Constraints
* Examples
* Output format

```text
Application
     ↓
Prompt Template
     ↓
User Variables
     ↓
Foundation Model
     ↓
Consistent Output
```

# 9. Retrieval-Augmented Generation (RAG) ⭐⭐⭐⭐⭐

RAG allows an application to provide **external information to the foundation model at runtime**.

Important:

> **RAG does NOT change the foundation model.**

Instead:

```text
User Question
      ↓
External Data Store
      ↓
Relevant Information
      ↓
Foundation Model
      ↓
Response
```

The external information could include:

* Company private data
* HR policies
* Jira information
* Product information
* Other organizational knowledge

---

# 10. Why RAG?

Foundation models may not know your organization's private or recently updated information.

Example:

```text
User:
"What is our latest HR policy?"
```

Instead of relying only on the model:

```text
Question
   ↓
Company Knowledge Base
   ↓
Latest HR Policy
   ↓
LLM
   ↓
Answer
```

The model receives the relevant facts before generating the answer.

This makes the response more relevant and can reduce the tendency to invent information about private/current data.

---

# 11. RAG Data Preparation ⭐⭐⭐⭐⭐

Before RAG can retrieve information, source data needs to be prepared.

```text
Raw Data
   ↓
Document Chunking
   ↓
Embedding Model
   ↓
Embeddings
   ↓
Vector Store
```

### Source data examples

* Enterprise documents
* HR policies
* Jira tickets
* Product images
* Other private information

---

## Document Chunking

Large documents are divided into smaller pieces called **chunks**.

```text
Large Document
      ↓
┌─────────────┐
│ Chunk 1     │
├─────────────┤
│ Chunk 2     │
├─────────────┤
│ Chunk 3     │
└─────────────┘
```

These chunks are then converted into embeddings.

---

# 12. Embeddings ⭐⭐⭐⭐⭐

An embedding is a **numerical representation of data** such as:

* Text
* Images
* Video
* Audio

The representation exists in a **high-dimensional vector space**.

```text
Text / Image
     ↓
Embedding Model
     ↓
Numerical Vector
```

The important idea is that embeddings capture **semantic relationships**.

For example:

```text
horse ↔ animal
```

will be semantically closer than:

```text
horse ↔ New York
```

---

# 13. Vector Store

A vector store/database stores embeddings and allows them to be searched efficiently.

```text
Documents
    ↓
Embeddings
    ↓
Vector Store
    ↓
Semantic Search
```

The purpose is to find information based on **meaning/similarity**, rather than only exact keyword matching.

The transcript mentions algorithms such as **K-nearest neighbor (KNN)** being used behind vector searching.

---

Serverless option for OpenSearch workloads.

# 17. Fine-Tuning ⭐⭐⭐⭐⭐

Fine-tuning **changes the model**.

You start with a pre-trained foundation model and train it further using **domain-specific labeled data**.

```text
Pre-trained Model
       ↓
Labeled Domain Data
       ↓
Additional Training
       ↓
Updated Model Weights
       ↓
Custom / Fine-Tuned Model
```

### Key Difference

```text
RAG:
Model unchanged ❌
External knowledge added ✅

Fine-Tuning:
Model changed ✅
Weights updated ✅
```

---

# 18. Fine-Tuning Use Case

Example from the transcript:

Healthcare researchers want a model better aligned with:

* Current medical practices
* Current terminology
* Changes in patient demographics

They can provide domain-specific labeled data to improve the model's performance for that domain.

---

# 19. Domain Adaptation Fine-Tuning

Also described as **transfer learning** in the transcript.

Purpose:

> Adapt the model to the language and terminology of a specific domain.

Example:

```text
Pre-trained Model
       ↓
Medical Research Papers
       +
Medical Labeled Examples
       ↓
Fine-Tuned Model
       ↓
Healthcare Application
```

The model becomes better at understanding:

* Industry terminology
* Domain vocabulary
* Writing style
* Domain context

---

# 20. Instruction-Based Fine-Tuning

Uses **prompt-response pairs** as labeled examples.

```text
Prompt 1 → Response 1
Prompt 2 → Response 2
Prompt 3 → Response 3
...
        ↓
Fine-Tuning
        ↓
Custom Model
```

The goal is to improve performance for a specific instruction/task format.

---

# 21. Fine-Tuning Example — Dog Breeds

Suppose a pre-trained image model already recognizes:

```text
Dogs
Cats
Cars
Pens
Pencils
...
```

But your application only needs:

```text
Dog Breed Classification
```

Provide labeled images of different dog breeds.

```text
Pre-trained Model
       ↓
Dog Breed Images + Labels
       ↓
Fine-Tuning
       ↓
Custom Dog Breed Model
```

The model's weights become more focused on features useful for distinguishing dog breeds.

# 29. Amazon Bedrock Guardrails ⭐⭐⭐⭐⭐

```text

    ↓
Guardrails
    ↓
Foundation Model
    ↓
Guardrails
    ↓
Final Response
```

Guardrails can evaluate both:

### Input

Check whether the user request contains:

* Hate
* Insults
* Violence
* Blocked/custom words
* PII

### Output

Check whether the model response contains prohibited or sensitive information.

# 30. PII Protection

PII = **Personally Identifiable Information**.

Examples mentioned:

* License numbers
* Date of birth
* Addresses
* Email
* Phone numbers

Guardrails can detect sensitive information and **redact it** before the final response reaches the user.

Example:

```text
Model Response:
"You can reach me at 555-123-4567"

        ↓
Guardrail detects PII

        ↓
Redacts phone number

        ↓
Safe Response
```

This helps protect user privacy.

# 34. Temperature ⭐⭐⭐⭐⭐

Temperature controls the **randomness/creativity** of the generated response.

### Low temperature

More predictable / less random.

```text
Temperature ↓
      ↓
Less randomness
      ↓
More consistent output
```

Useful for scenarios where predictable responses are preferred.

Example:

```text
Banking application
```

### Higher temperature

More randomness/diversity.

```text
Temperature ↑
      ↓
More randomness
      ↓
More diverse responses
```

Useful for:

* Poetry
* Brainstorming
* Creative writing

### Simplified understanding

```text
0 → More deterministic
1 → More creative/random
```

The transcript uses this simplified range for explanation.

---

# 35. Top P ⭐⭐⭐⭐⭐

Top P controls the set of candidate tokens considered based on their **cumulative probability**.

Conceptually:

```text
Possible Tokens
      ↓
Probability
      ↓
Keep tokens until
cumulative probability reaches P
      ↓
Choose from those
```

Example from the transcript:

```text
Top P = 0.9
```

means the model considers tokens whose cumulative probability reaches approximately 90%.

### Difference from Temperature

```text
Temperature
→ Controls randomness

Top P
→ Controls probability mass considered
```

The transcript explicitly notes that the mathematical details are beyond this introductory explanation.

---

# 36. Top K

Top K limits the model to the **K most probable tokens**.

Example:

```text
Top K = 4
```

The model considers the four most probable candidate tokens.

```text
Possible tokens:

1. Token A ⭐
2. Token B ⭐
3. Token C ⭐
4. Token D ⭐
5. Token E
6. Token F
...
```

Only the top four are considered.

### Top K vs Top P

```text
Top K
→ Number of candidate tokens

Top P
→ Cumulative probability threshold
```

Some models support Top K, while others may only provide Top P.

---

# 37. Maximum Tokens

Developers can limit the maximum number of tokens generated.

Why?

### Control Response Size

```text
max_tokens = 200
```

limits how much output can be generated.

### Control Cost

The transcript notes that token usage affects pricing.

Therefore:

```text
More tokens
    ↓
More processing
    ↓
Higher cost
```

---

# 38. Stop Sequence

A stop sequence tells the model:

> Stop generating when this sequence is encountered.

Example:

```text
Stop sequence = "."
```

The model stops when it encounters the configured sequence.

---

# 39. System Prompt

A system prompt can establish how the model should behave.

Example:

```text
System Prompt:
"Answer like a technical trainer."
```

Then the user doesn't need to repeatedly specify:

```text
"Answer like a technical trainer."
```

for every question.

The behavior is established through the system configuration.

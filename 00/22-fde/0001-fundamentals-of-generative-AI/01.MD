## 1. AI vs Machine Learning

### Artificial Intelligence (AI)

AI is the broader field of building systems capable of performing tasks that typically require human intelligence.

Examples:

* Reasoning
* Prediction
* Classification
* Recommendation
* Speech recognition
* Image understanding
* Decision support

### Machine Learning (ML)

ML is a subset of AI where systems **learn patterns from historical data** instead of being explicitly programmed with every rule.

### Traditional Programming

```text
Rules + Input
     ↓
   Output
```

Example:

```text
IF customer buys shoes
THEN recommend socks
```

The developer manually defines the rules.

### Machine Learning

```text
Historical Data
      ↓
  ML Algorithm
      ↓
    Model
      ↓
New Data → Prediction
```

The model learns patterns from historical examples.

---

# 2. Core ML Concepts

## Features

**Features = input attributes used by the model to make a prediction.**

Example: House price prediction

```text
Features:
- House size
- Number of bedrooms
- Location
- Number of bathrooms
```

---

## Label

**Label = the actual outcome that the model is trying to predict.**

Example:

```text
Features → size, bedrooms, location
Label    → actual selling price
```

For fraud detection:

```text
Features → transaction information
Label    → Fraud / Not Fraud
```

> Labels are primarily associated with **supervised learning**.

---

## Weights

Weights represent how strongly individual features influence the prediction.

During training, the model adjusts its weights to reduce prediction errors.

Example:

```text
Location       → High weight
House size     → High weight
Bedrooms       → Medium weight
House color    → Very low weight
```

### Key idea

```text
Feature → Weight → Contribution to prediction
```

---

## Model

A **model** is the learned representation of patterns from training data.

```text
Training Data
      ↓
 Learning Algorithm
      ↓
    Trained Model
      ↓
 New Data
      ↓
   Prediction
```

The model should be able to make predictions on **unseen data**.

# 3. Types of Machine Learning ⭐⭐⭐

There are three major categories discussed in this material:

| Type          | Training Data          | Main Goal          | Example               |
| ------------- | ---------------------- | ------------------ | --------------------- |
| Supervised    | Labeled                | Predict an outcome | Fraud detection       |
| Unsupervised  | Unlabeled              | Find patterns      | Customer segmentation |
| Reinforcement | Environment + feedback | Learn actions      | Self-driving / games  |

---

# 4. Supervised Learning

The model learns from **labeled historical data**.

```text
Labeled Data
     ↓
 Training
     ↓
 Model
     ↓
Unseen Data
     ↓
 Prediction
```

Two important types:

## Classification

Predicts a **categorical/discrete value**.

Examples:

```text
Email → Spam / Not Spam

Transaction → Fraud / Not Fraud

Image → Cat / Dog
```

### Think:

> **Classification = Which category?**

---

## Regression

Predicts a **numerical/continuous value**.

Examples:

```text
House → $500,000

Insurance → $1,200

Demand → 25,000 units
```

### Think:

> **Regression = How much / what number?**

---

# 5. Unsupervised Learning

The data does **not have predefined labels**.

The algorithm attempts to discover patterns, structures, or relationships.

## Clustering

Groups similar data points.

Example:

```text
Customers
    ↓
Clustering
    ↓
┌───────────────┐
│ Frequent      │
│ shoppers      │
├───────────────┤
│ Bargain       │
│ hunters       │
├───────────────┤
│ Occasional    │
│ visitors      │
└───────────────┘
```

Useful for:

* Customer segmentation
* Marketing
* Recommendation strategies
* Behavioral analysis

---

## Anomaly Detection

Identifies data that behaves differently from the normal pattern.

Examples:

```text
Normal website traffic
        ↓
Sudden traffic spike
        ↓
    Anomaly
```

Use cases:

* Fraud detection
* Network monitoring
* Server monitoring
* Healthcare monitoring
* Unusual website traffic

---

# 6. Reinforcement Learning

Reinforcement learning is based on an **agent interacting with an environment**.

```text
       Environment
            ↑
            │
         Reward
            │
            ↓
          Agent
            │
          Action
            ↓
       Environment
```

The agent learns through:

```text
Action
  ↓
Reward / Penalty
  ↓
Learning
  ↓
Better future action
```

Examples:

* Robotics
* Games
* Autonomous vehicles

> For FDE AWS, understand the concept and use cases. You do not need deep RL mathematics at this stage.

# 9. ML Limitations

ML is **not automatically the right solution** for every problem.

### Historical Data Dependency

Models learn from historical data.

If the real world changes significantly, model performance can degrade.

```text
Old training data
       ↓
Changed real world
       ↓
Poor predictions
```

### Data Quality

Poor-quality data produces poor models.

Important issues:

* Missing values
* Incorrect values
* Duplicates
* Outliers
* Inconsistent formats
* Insufficient data

### High-Risk Decisions

Some scenarios require human oversight.

Examples discussed:

* Medical decisions
* Aviation
* Criminal sentencing
* Child welfare

Consider:

* Accuracy
* Explainability
* Fairness
* Accountability
* Human oversight

### Real-Time Constraints

Some ML workloads may be computationally expensive and unsuitable for strict real-time requirements.

# 10. ML Development Lifecycle ⭐⭐⭐⭐⭐

This is one of the most important sections.

```text
Business Problem
       ↓
Problem Formulation
       ↓
Data Collection
       ↓
Data Exploration
       ↓
Data Preparation
       ↓
Feature Engineering
       ↓
Model Training
       ↓
Model Evaluation
       ↓
Hyperparameter Tuning
       ↓
Deployment
       ↓
Inference
       ↓
Monitoring
```

---

## Step 1 — Business Problem

First ask:

> **Do we actually need ML?**

Not every problem needs ML.

Simple deterministic problems may be better solved using:

* Rules
* SQL
* Traditional application logic
* Spreadsheets

ML becomes more appropriate when the problem involves complex patterns, large amounts of data, and predictions that are difficult to express through fixed rules.

---

## Step 2 — Problem Formulation

Convert the business problem into an ML problem.

Example:

```text
Business Problem:
Detect fraudulent transactions

        ↓

ML Problem:
Supervised Learning

        ↓

Problem Type:
Classification

        ↓

Output:
Fraud / Not Fraud
```

This is an important FDE skill.

---

## Step 3 — Data Collection

Collect historical data from sources such as:

* Databases
* APIs
* Logs
* Websites
* Transactions
* Other data repositories

---

## Step 4 — Data Exploration

Before training, understand the data.

Look for:

* Data distribution
* Data balance
* Relationships between features
* Patterns
* Anomalies
* Missing information

---

## Step 5 — Data Preparation

Clean and transform the data.

Typical problems:

```text
Missing values
Duplicates
Incorrect values
Outliers
Inconsistent formats
```

---

## Step 6 — Model Training

Feed prepared data into an ML algorithm.

The model learns parameters that reduce the difference between:

```text
Predicted Value
      vs
Actual Value
```

That difference is the **error/loss** that training attempts to minimize.

---

## Step 7 — Model Evaluation

Use test data to determine whether the model performs well on unseen data.

Questions:

* Is the model accurate enough?
* Is it making too many errors?
* Does it need more data?
* Does it need better features?
* Does it need tuning?

---

## Step 8 — Hyperparameter Tuning

Hyperparameters are configurable settings used to improve model performance.

Think:

```text
Model
  ↓
Adjust settings
  ↓
Train again
  ↓
Evaluate
  ↓
Improve
```

> **Parameters** are learned during training.
> **Hyperparameters** are settings selected/tuned around the training process.

# 11. Training vs Inference ⭐⭐⭐⭐⭐

This distinction is critical.

## Training

```text
Historical Data
      ↓
ML Algorithm
      ↓
Trained Model
```

Training is where the model learns patterns.

## Inference

```text
New Data
   ↓
Trained Model
   ↓
Prediction
```

Example:

```text
Historical transactions
        ↓
Train fraud model
        ↓
Deploy model
        ↓
New transaction
        ↓
Inference
        ↓
Fraud / Not Fraud
```

> **Training = learning**
> **Inference = using the learned model**

# 15. SageMaker Inference Options ⭐⭐⭐⭐⭐

This is particularly important for AWS architecture decisions.

| Inference           | Use When                    | Key Characteristic                    |
| ------------------- | --------------------------- | ------------------------------------- |
| **Real-time**       | Immediate response required | Low latency                           |
| **Batch Transform** | Large offline workloads     | No immediate response                 |
| **Asynchronous**    | Long-running requests       | Larger payload / relaxed latency      |
| **Serverless**      | Intermittent traffic        | No persistent endpoint infrastructure |

---

## Real-Time Inference

Application sends a request and expects a quick prediction.

```text
Application
     ↓
SageMaker Endpoint
     ↓
Prediction
```

Examples:

* Fraud detection
* Recommendation engines
* Interactive applications

Use when **latency matters**.

---

## Batch Transform

Process a large dataset offline.

Example:

```text
10,000 images
      ↓
Batch Transform
      ↓
10,000 predictions
```

Use when:

* Results are not needed immediately
* Large amounts of data need processing
* Cost efficiency is important

---

## Asynchronous Inference

For requests that may take longer to process.

Example:

```text
Large Loan Document
       ↓
SageMaker Async
       ↓
Long-running processing
       ↓
Result
```

Use when:

* Payloads are large
* Processing takes significant time
* Sub-second latency isn't required

---

## Serverless Inference

AWS manages the underlying inference infrastructure.

Good for workloads with:

```text
Low traffic
   ↓
Idle period
   ↓
Traffic spike
   ↓
Scale
```

Important tradeoff:

> **Serverless inference can have cold-start latency.**

Therefore, it isn't ideal for workloads requiring consistently ultra-low latency.

# 18. FDE Interview Quick Answers

### What is ML?

> Machine learning is a subset of AI where models learn patterns from historical data to make predictions on new data rather than relying entirely on explicitly programmed rules.

### Classification vs Regression?

> Classification predicts categorical values, such as fraud/not fraud. Regression predicts continuous numerical values, such as house price.

### Training vs Inference?

> Training is the process of learning patterns from historical data. Inference is using the trained model to generate predictions for new data.

### When would you use SageMaker?

> When we need to build, train, deploy, host, or monitor custom ML models and manage the ML lifecycle on AWS.

### Real-time vs Batch inference?

> Real-time inference is for low-latency predictions needed immediately. Batch processing is for large offline workloads where immediate results aren't required.

### When would you use serverless inference?

> For intermittent workloads where there can be idle periods and the application can tolerate cold-start latency.

### Why use managed AI services?

> If AWS already provides a managed service for the required capability, it can avoid the complexity and cost of collecting training data, building, deploying, and maintaining a custom model.

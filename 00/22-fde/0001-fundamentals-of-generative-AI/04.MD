# AWS FDE — Responsible AI & Responsible ML

## 1. Responsible AI ⭐⭐⭐⭐⭐

Responsible AI is a set of principles and practices that ensure AI systems operate:

* Ethically
* Transparently
* With accountability

The goal is to:

* Build trust
* Reduce risks
* Protect users
* Support appropriate and responsible AI deployment

---

# 2. Key Responsible AI Principles ⭐⭐⭐⭐⭐

The transcript covers these principles:

```text id="8xg5h1"
Responsible AI
├── Fairness
├── Privacy & Security
├── Explainability
├── Governance
├── Robustness
└── Transparency
```

## Fairness

AI systems should avoid unfairly discriminating against individuals or groups.

Examples of factors that can create unfair outcomes:

* Gender
* Ethnicity
* Age

Goal:

> Prevent biased outcomes that disadvantage particular groups.

---

## Privacy & Security

User data and personal information must be protected from:

* Unauthorized access
* Unauthorized exposure

---

## Explainability

Users should be able to understand **why an AI system produced a particular decision or output**.

Example:

```text id="z4d8e4"
Loan Application
      ↓
AI Model
      ↓
Rejected
      ↓
Why?
      ↓
Low income
+
High debt-to-income ratio
```

Explainability helps with:

* Evaluation
* Auditing
* Trust

---

## Governance

Governance means having:

* Processes
* Policies
* Frameworks
* Standards
* Regulations

to establish and enforce responsible AI practices.

---

## Robustness

A robust AI system should be:

* Reliable
* Fault tolerant
* Consistent
* Predictable

It should continue operating appropriately even when unexpected situations occur.

---

## Transparency

Organizations should clearly communicate:

* AI capabilities
* Limitations
* Potential risks

This allows stakeholders to make informed decisions about how and where the AI system should be used.

---

# 3. Human-Centered AI ⭐⭐⭐⭐

Human-centered AI means designing AI systems around the:

* Needs
* Goals
* Wellbeing
* Understanding

of human users.

The system should consider the user's:

* Technical expertise
* Mental model
* Expectations

### Example

If an AI rejects a loan application, the user shouldn't simply see:

```text id="2oyr4p"
Loan Rejected
```

Instead, the system should provide an understandable explanation.

---

Developers should acknowledge and consider potential bias in:

* Training data

* Model outputs

Responsible AI isn't a one-time activity.

Organizations should:

```text id="z0n0p7"
Build

Collect User Feedback
 ↓
Evaluate
 ↓
Improve
 ↓

```

Explainability and responsible behavior should evolve with changing user needs.

# 5. Reinforcement Learning from Human Feedback (RLHF) ⭐⭐⭐⭐

RLHF = **Reinforcement Learning from Human Feedback**

Human reviewers evaluate model responses.

Example:

```text id="h0vhz3"
User Prompt
     ↓
Model generates:
A
B
C
     ↓
Human reviewers rank responses
     ↓
Reward signal
     ↓
Model optimization
```

The goal is to align model behavior more closely with **human preferences/values**.

Benefits mentioned:

* Better alignment with human values
* Improved safety
* Improved reliability
* Reduced harmful or biased outputs

The transcript explicitly notes that real RLHF implementations are much more complex than this simplified example.

# 7. Responsible Data Collection ⭐⭐⭐⭐⭐

Responsible AI starts **before model training**.

The training dataset needs to be:

* Representative
* Inclusive
* High quality
* Privacy-conscious
* Properly balanced

---

## Representative Data

If an application serves people from different groups, the dataset should represent those groups.

Example:

```text id="6j1z1w"
Consumer Application

Age groups
Gender
Socioeconomic backgrounds
Different preferences
        ↓
Representative Dataset
```

A recommendation system shouldn't be trained using data representing only one narrow group of users.

---

## Remove PII

Training data should be carefully reviewed to remove **Personally Identifiable Information (PII)** when it isn't required.

Example mentioned:

> Employee performance review data should be cleaned to remove PII before being used for model creation.

---

# 8. Balanced Dataset

A dataset is imbalanced when one class has dramatically more examples than another.

Example:

```text id="xj8y1h"
Fraud transactions       → 200
Legitimate transactions   → 200,000
```

This creates a highly imbalanced dataset.

The model may not learn enough about the minority class.

For fraud detection, you need enough examples of both:

```text id="d2x5e5"
Fraud
+
Non-Fraud
```

to properly learn the distinction.

---

# 9. Bias vs Variance ⭐⭐⭐⭐⭐

These are important ML concepts discussed in the transcript.

## Bias

The transcript describes bias as the gap between the **predicted value and actual value**.

Example:

```text id="8g2bq1"
Predicted → $20,000
Actual    → $200,000

Large difference → High Bias
```

High bias indicates the model is not capturing the underlying relationship well.

---

## Variance

Variance describes how much the model's predictions vary.

Example:

```text id="4r9e9d"
Same input

Prediction 1 → $20,000
Prediction 2 → $30,000
Prediction 3 → $15,000
```

Large variation → High variance.

---

# 10. High Bias vs High Variance

### High Bias

The model is often:

* Oversimplified
* Rigid
* Less flexible

This is associated with **underfitting**.

```text id="7p7f1v"
Training Data
     ↓
Model learns too little
     ↓
Poor generalization
```

---

### High Variance

The model behaves inconsistently and can become too closely fitted to training data.

This is associated with **overfitting**.

```text id="h6j0fh"
Training Data
     ↓
Model learns too much detail
     ↓
Poor performance on unseen data
```

---

## Desired State

```text id="6xyr2b"
       Low Bias
           +
      Low Variance
           ↓
 Accurate + Reliable Model
```

Think of this as the **bull's-eye** target.

---

     ├── 10% → Validation

### Training Set

Used to train the model.

### Validation Set

Used during model development to evaluate/tune the model.

### Test Set

Kept aside for evaluating the final model.

The transcript refers to this overall process in the context of cross-validation/data splitting.

# 12. Data Augmentation ⭐⭐⭐⭐

Data augmentation can help when the dataset is insufficient or imbalanced.

### Example — Fraud

If you have:

```text id="5w7a2m"
200 Fraud
200,000 Non-Fraud
```

additional synthetic examples can be generated to increase the minority class.

---

### Example — Images

Image datasets can be expanded by:

* Rotation
* Flipping
* Adding noise

This increases variety in the training data.

---

# 13. Regularization ⭐⭐⭐⭐

Regularization helps reduce **overfitting**.

It adds a penalty that discourages the model from becoming unnecessarily complex.

```text id="5q1o4s"
Complex Model
     ↓
Regularization
     ↓
Penalize excessive complexity
     ↓
Better generalization
```

---

# 14. Early Stopping

Early stopping monitors training and stops it **before the model begins to overfit**.

```text id="3k2v8h"
Training
   ↓
Training improves
   ↓
Continue
   ↓
Performance starts degrading
   ↓
STOP
```

Then evaluate the model.

---

# 15. Hyperparameter Tuning

Hyperparameter tuning involves adjusting model settings to improve performance.

Examples mentioned:

* Learning rate
* Batch size

```text id="p6iz1s"
Change Hyperparameters
        ↓
Train
        ↓
Validate
        ↓
Adjust
        ↓
Repeat
```

Together, these techniques help build more robust and reliable models.

---

# 16. Transparency vs Explainability ⭐⭐⭐⭐⭐

These two concepts are related but different.

## Transparency

Focus:

> **What is the model doing?**

Understanding the model's internal behavior/logic.

---

## Explainability

Focus:

> **Why did the model produce this particular result?**

Example:

```text id="m1l3i6"
Loan rejected

Explanation:
- Low income
- High debt-to-income ratio
```

---

## Key Difference

```text id="khj4z0"
Transparency
→ Understand the model/system

Explainability
→ Understand a particular decision/output
```

---

# 17. Accuracy vs Explainability

There can be a trade-off.

### Simple Model

```text id="8h3e2w"
Simple
 ↓
More interpretable
 ↓
Potentially lower accuracy
```

### Complex Model

```text id="b8c5l0"
Complex
 ↓
Potentially higher accuracy
 ↓
Harder to explain
```

### High-Stakes Applications

For applications involving major consequences, explainability may be more important than achieving the absolute highest accuracy.

For simpler use cases such as object recognition in a product catalog, accuracy may be the primary goal.

# 21. AWS Artifact vs AWS Audit Manager ⭐⭐⭐⭐⭐

This distinction is important.

## AWS Audit Manager

Focuses on **your AWS environment/account**.

```text id="4r1x1p"
Your AWS Account
      ↓
Audit Manager
      ↓
Evaluate your controls / activities
      ↓
Compliance evidence
```

It helps determine whether your policies, procedures, and controls are operating effectively.

---

## AWS Artifact

Provides access to AWS's own **security and compliance reports/evidence**.

```text id="v4lq1k"
AWS Infrastructure
      ↓
Third-party audits
      ↓
Compliance Reports
      ↓
AWS Artifact
```

### Easy way to remember

```text id="h9w9zz"
Audit Manager
→ "Is MY AWS environment compliant?"

Artifact
→ "Is AWS's infrastructure compliant?"
```

The transcript specifically contrasts these two services in this way.

# 22. SageMaker Model Monitor ⭐⭐⭐⭐⭐

Once a model is deployed to production, it needs continuous monitoring.

```text id="f3l5m6"
Production Model
      ↓
SageMaker Model Monitor
      ↓
Detect Changes / Drift
      ↓
CloudWatch Alerts
```

It can monitor:

* Data drift
* Prediction data
* Outliers
* Data distribution changes
* Prediction accuracy changes

---

## Data Drift

Data drift means the distribution of incoming production data changes compared with the training data.

```text id="g8m6p1"
Training Data Distribution
          ↓
       Model
          ↓
Production Data
          ↓
Distribution Changed?
          ↓
       Data Drift
```

Model Monitor can use built-in rules or custom rules.

Alerts can be sent to **CloudWatch** when rules are violated.

# 26. Amazon Augmented AI (A2I) ⭐⭐⭐⭐⭐

Amazon Augmented AI combines **machine learning with human review**.

The key use case in the transcript is **low-confidence predictions**.

```text id="j4z7km"
Input
 ↓
ML Model
 ↓
Prediction
 ├── High Confidence
 │       ↓
 │   Return Result
 │
 └── Low Confidence
         ↓
     Human Review
         ↓
     Final Result
```

### Why?

The system combines:

```text id="j1y5z7"
ML
→ Speed + Scalability

Human
→ Judgment + Expertise
```

This is a **human-centered AI approach**.

---

## Human Reviewers

Reviewers can come from:

* Internal company workforce
* Private workforce
* External/vendor workforce

The reviewed data can be stored for further use.

# Generative AI Fundamentals

## 1. AI → ML → Deep Learning → Generative AI

The hierarchy discussed in the transcript is:

```text
Artificial Intelligence
        ↓
Machine Learning
        ↓
Deep Learning
        ↓
Generative AI
```

### Deep Learning

Deep Learning is a subset of Machine Learning that uses **artificial neural networks with multiple layers** to learn complex patterns in data.

A neural network has:

```text
Input Layer
     ↓
Hidden Layers
     ↓
Output Layer
```

* **Input layer** receives the data.
* **Hidden layers** process the information and identify patterns/features.
* **Output layer** produces the final result.

Deep learning can automatically learn useful features from data without humans explicitly defining all of them.

Example mentioned:

> Amazon Rekognition uses deep learning/neural networks for image and video analysis.

---

# 2. Generative AI

Generative AI is presented as a specialized subset of deep learning focused on **generating new content**.

```text
Deep Learning
      ↓
Generative AI
      ↓
Generate New Content
```

A Generative AI model learns from existing examples and can generate new content based on what it learned.

Examples:

* Text
* Code
* Images
* Other generated content

Generative AI models are commonly based on very large pre-trained models called **Foundation Models (FMs)**.

---

# 3. Traditional ML Models vs Foundation Models

### Traditional ML

Traditionally, data scientists would:

```text
Collect Data
    ↓
Label Data
    ↓
Select Features
    ↓
Choose Algorithm
    ↓
Train Model
    ↓
Specific Task
```

A model was generally built for a particular task.

For example:

```text
Model 1 → Fraud Detection
Model 2 → Recommendation
Model 3 → Classification
```

If another task was needed, another model would typically have to be developed.

---

# 4. Foundation Models (FM) ⭐⭐⭐⭐⭐

A **Foundation Model** is a large pre-trained model that can be adapted to perform multiple downstream tasks.

Instead of:

```text
Task 1 → Train Model 1
Task 2 → Train Model 2
Task 3 → Train Model 3
```

we can have:

```text
                    Foundation Model
                    /       |       \
                   ↓        ↓        ↓
              Chatbot   Summarization  Generation
```

This is why it is called a **foundation**: the pre-trained model provides a starting point that can be adapted for different tasks.

---

# 5. Foundation Model Pre-training

Foundation models are trained on **very large amounts of data**.

The transcript mentions:

* Internet content
* Wikipedia
* Books
* Social media
* Structured data
* Unstructured data
* Other large datasets

Labeled examples are not necessarily required during the initial pre-training process.

The transcript refers to this as **self-supervised learning**, where the model can generate training signals/labels from the data itself.

During pre-training, the model learns:

* Meaning of words
* Context
* Relationships between words
* Language patterns
* How sentences are formed

Example:

```text
bank

→ financial institution
→ river bank
```

The model learns that the meaning depends on context.

# 9. Transformer Architecture ⭐⭐⭐⭐⭐

The transcript identifies the **Transformer architecture** as a key architecture behind modern language models.

A major component is:

> **Self-Attention**

Self-attention allows the model to determine the importance of different words/tokens relative to one another.

Example:

```text

"She took a bow after the performance."
```

The word **"bow"** has different meanings.

The model uses surrounding context to understand which meaning is relevant.

# 10. Self-Attention

Self-attention allows the model to consider the relationship between words across the input.

Conceptually:

```text
Sentence
   ↓
Look at all relevant words
   ↓
Determine relationships
   ↓
Understand context
   ↓
Generate output
```

The transcript also mentions **multi-head self-attention**, which allows the model to consider different relationships within the input.

You do **not** need the mathematical implementation at this stage.

# 11. How an LLM Processes Input ⭐⭐⭐⭐⭐

The transcript explains a simplified flow.

```text
User Input
    ↓
Tokenization
    ↓
Encoding
    ↓
Self-Attention / Model Processing
    ↓
Probability Evaluation
    ↓
Next Token
    ↓
Generated Output
```

---

## Step 1 — Tokenization

The input is broken into smaller pieces called **tokens**.

Tokens can represent:

* Words
* Parts of words
* Punctuation
* Special tokens

Example conceptually:

```text
"Hello world!"

        ↓

["Hello", "world", "!"]
```

Tokenization provides a standardized representation for processing.

---

## Step 2 — Encoding

The tokens are converted into **numerical representations** so that the model can process them mathematically.

```text
Text
 ↓
Tokens
 ↓
Numerical Representation
```

Conceptually:

```text

        ↓

Probability evaluation

        ↓

```

The process continues token by token.

```text

   ↓

   ↓

   ↓

```

The transcript summarizes LLMs as highly sophisticated **pattern-matching/completion systems** that learn relationships between words from massive amounts of training data.

# 14. Generative AI Limitations ⭐⭐⭐⭐⭐

## Hallucination

The model can generate information that **does not actually exist**, while presenting it confidently.

Example:

```text
Real information
      +
Fabricated information
      ↓
Confident but false answer
```

This is called a **hallucination**.

---

## Inaccuracy

The model can produce an incorrect answer even when it isn't inventing something completely fictional.

For example:

* Incorrect calculation
* Outdated information
* Misinterpreted information

### Hallucination vs Inaccuracy

```text
Hallucination
→ Fabricated / nonexistent information

Inaccuracy
→ Incorrect answer or information
```

---

## Interpretability

Generative AI models can behave like a **black box**.

You provide:

```text
Question
   ↓
Model
   ↓
Answer
```

But it can be difficult to determine exactly:

* Which information influenced the answer
* How the model reached the output
* Why it selected a particular response

This can be a concern for **high-stakes applications** where decisions need to be explained or verified.

---

## Nondeterministic Answers

The same question can produce different answers.

```text
Same Prompt
    ↓
 ┌──────────────┐
 ↓              ↓
Answer A      Answer B
```

Therefore, consistent and predictable behavior can sometimes be difficult to guarantee.

---

## Verbose / Chatty Responses

Generative AI may generate more content than requested.

Example:

```text
Prompt:
"What is S3?"

Expected:
3 sentences

Model:
Several paragraphs
+ explanation
+ examples
+ additional information
```

The transcript notes that prompting can be used to constrain the response, such as requesting a specific number of sentences or bullet points.


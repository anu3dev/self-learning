# Agentic AI — Fundamentals & AWS Support

## Evolution of AI Systems

AI systems have evolved from simple prompt-based applications toward autonomous systems capable of reasoning, planning, and executing complex workflows.

### 1. Early Generative AI

Early Generative AI systems were primarily used for simple content generation through prompts.

Examples:

- Generate paragraphs
- Generate images
- Generate code

These systems were typically:

- **Singleton** — one model/application handles the request.
- **Reactive** — responds only when prompted.
- **Stateless** — does not maintain context across interactions.

```text
User Prompt
     ↓
Generative AI Model
     ↓
Output
```

---

### 2. Agent for Generative AI

The next stage introduced **AI agents** that can reason about a task and break complex problems into smaller steps.

Agents can:

- Use reasoning frameworks such as **ReAct**
- Break complex tasks into simpler steps
- Access external information
- Interact with APIs and tools
- Perform multiple actions to complete a task

```text
Complex Task
     ↓
Reason
     ↓
Break into Steps
     ↓
Use Tools / APIs
     ↓
Execute Steps
     ↓
Final Result
```

---

### 3. Multi-Agent Systems

The next evolution is **Multi-Agent AI**, where multiple autonomous agents work together.

Each agent can specialize in a particular task and collaborate with other agents to complete complex workflows.

```text
                 Main Task
                    ↓
        ┌───────────┼───────────┐
        ↓           ↓           ↓
    Agent A      Agent B      Agent C
   Researcher    Analyst      Executor
        └───────────┼───────────┘
                    ↓
               Final Result
```

Multi-agent systems can execute multi-step workflows and adapt to changing conditions.

---

# Agentic AI Fundamentals

## Definition

**Agentic AI** refers to autonomous software systems that use AI to **reason, plan, and complete tasks** on behalf of humans or other systems.

Unlike a simple GenAI application that generates a response, an agent can determine **what actions need to be performed** and execute them using available tools.

---

## Core Capabilities

Agentic AI systems can:

- Perform **multi-step tasks**
- Maintain **context**
- Access multiple data sources
- Use external tools and APIs
- Automate workflows
- Reason iteratively
- Adapt actions based on previous results

### Basic Agent Flow

```text
Task
 ↓
Reason
 ↓
Plan
 ↓
Act
 ↓
Observe Result
 ↓
Reason Again
 ↓
Next Action
 ↓
Final Result
```

---

# Building Agentic AI Systems

Agentic AI systems can be built using different architectural patterns depending on how much autonomy is required.

## 1. Workflow Agent

A **Workflow Agent** is suitable when the task follows **predetermined stages**.

The workflow controls how the task progresses.

### Common Workflow Patterns

#### Serial Pattern — Prompt Chaining

Tasks execute sequentially.

```text
Step 1
  ↓
Step 2
  ↓
Step 3
  ↓
Final Result
```

Each step's output can become the input for the next step.

---

#### Parallelization Pattern

Multiple tasks execute simultaneously.

```text
             Task
               ↓
       ┌───────┼───────┐
       ↓       ↓       ↓
    Task A  Task B  Task C
       └───────┼───────┘
               ↓
          Final Result
```

Useful when tasks are independent and can run concurrently.

---

#### Routing Pattern

The system determines which path should handle the request.

```text
                 Request
                    ↓
                  Router
              ┌─────┼─────┐
              ↓     ↓     ↓
           Agent A Agent B Agent C
```

---

#### Orchestration Pattern

A central orchestrator coordinates multiple tasks or components.

```text
              Orchestrator
             /      |      \
            ↓       ↓       ↓
         Task A   Task B   Task C
            \       |       /
             └──────┼──────┘
                    ↓
                Result
```

---

# 2. Autonomous Agent

An **Autonomous Agent** can determine its own next steps instead of following only predetermined stages.

### Agent Loop

The basic agent loop is:

```text
Perceive
   ↓
Reason
   ↓
Act
   ↓
Observe
   ↓
Reason Again
   ↓
Act
```

The agent continues this loop until the task is completed.

---

## ReAct Architecture

**ReAct = Reason + Act**

ReAct combines step-by-step reasoning with the ability to use external tools.

```text
Task
 ↓
Reason
 ↓
Choose Action
 ↓
Use Tool
 ↓
Observe Result
 ↓
Reason Again
 ↓
Next Action
```

This allows an agent to dynamically decide which action or tool is needed.

---

## RWO Architecture

**RWO = Reasoning Without Observation**

RWO separates reasoning into **modular components**, allowing reasoning to be handled independently from observation/action processing.

> Key idea: **Separate reasoning into modular components.**

---

# 3. Hybrid Agent

A **Hybrid Agent** combines workflow-based and autonomous approaches.

It can automatically determine whether a task should follow:

```text
Workflow
   OR
Autonomous Agent
```

Conceptually:

```text
                 Task
                   ↓
              Decision
              /       \
             ↓         ↓
        Workflow    Autonomous
          Agent        Agent
             \         /
              ↓       ↓
              Result
```

This approach provides flexibility when some tasks are predictable while others require autonomous reasoning.

---

# 4. Multi-Agent System

A **Multi-Agent System** coordinates multiple specialized agents to solve complex problems.

Each agent can focus on a specific responsibility.

```text
                 Complex Task
                      ↓
              Multi-Agent System
              /       |       \
             ↓        ↓        ↓
        Specialist  Specialist  Specialist
          Agent A     Agent B     Agent C
             \         |         /
              └────────┼────────┘
                       ↓
                  Final Result
```

Multi-agent systems are useful when a complex problem can be divided among specialized agents.

# 2. Fully Managed Solutions

## Amazon Bedrock Agents

**Amazon Bedrock Agent** provides managed capabilities for building autonomous AI agents.

Key components include:

| Component | Purpose |
|---|---|
| **Foundation Model** | Provides the AI reasoning/generation capability |
| **Agent Instructions** | Defines how the agent should behave |
| **Action Group** | Enables the agent to perform actions |
| **Knowledge Base** | Provides access to external knowledge |
| **Guardrail** | Provides security and content controls |

### Bedrock Agent Architecture

```text
              Amazon Bedrock Agent
                      │
       ┌──────────────┼──────────────┐
       ↓              ↓              ↓
 Foundation       Knowledge       Action
   Model            Base           Group
       │              │              │
       └──────────────┼──────────────┘
                      ↓
                  Guardrail
```

---

## Amazon Bedrock AgentCore

**Amazon Bedrock AgentCore** is designed to help move agent prototypes toward **production-ready agentic systems**.

It provides capabilities such as:

- Custom runtime features
- Identity management
- Observability
- Production-oriented agent infrastructure

```text
Agent Prototype
      ↓
AgentCore
      ↓
Production Agent System
```

---

# 3. DIY / Open Source Solutions

AWS also supports open-source approaches for building agentic AI systems.

## Strand Agents

**Strand Agents** is an open-source SDK for building AI agents using a **model-based approach**.

---

## A2A Protocol

**A2A (Agent-to-Agent)** is an open standard for communication between AI agents.

```text
Agent A
   ↓
A2A Protocol
   ↓
Agent B
```

It enables agents to communicate and collaborate.

---

## MCP — Model Context Protocol

**MCP (Model Context Protocol)** is an open standard for connecting AI systems to external tools and resources.

```text
AI Agent
    ↓
MCP
    ↓
External Tool / Resource
```

MCP allows AI systems to interact with external capabilities in a standardized way.

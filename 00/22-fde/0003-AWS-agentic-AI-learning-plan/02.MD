# Kiro — AI-Powered IDE

## What is Kiro?

**Kiro** is an AI-powered IDE built on **Visual Studio Code** that helps developers move from **prototype to production**.

Its key approach is **spec-driven development**, where high-level ideas are transformed into:

```text
High-Level Idea
      ↓
Requirements
      ↓
Design
      ↓
Tasks
      ↓
Implementation
```

---

## ⭐ Key Kiro Features

| Feature | Purpose |
|---|---|
| **Spec-Driven Development** | Converts ideas into structured requirements, design, and implementation tasks |
| **AI Chat** | Interact with AI using natural language for coding assistance |
| **Steering** | Provides persistent project knowledge and coding standards |
| **Agent Hooks** | Automates predefined actions based on development events |
| **MCP** | Connects Kiro to external tools, knowledge, and documentation |
| **Autopilot** | Allows Kiro to make related changes autonomously |
| **Supervised Mode** | Developer reviews and approves changes |

# Spec-Driven Development

Kiro's **Spec** system transforms an idea into structured implementation artifacts.

### Three Main Files

```text
requirements.md
      ↓
design.md
      ↓
tasks.md
```

### 1. Requirements

Defines:

- Project requirements
- User stories
- Acceptance criteria

### 2. Design

Defines:

- Architecture
- Components
- Data models
- Technical implementation considerations

### 3. Tasks

Defines the **implementation plan** as discrete tasks that Kiro can execute and track.

---

## Spec Workflow

```text
High-Level Idea
      ↓
Requirements
      ↓
Review / Clarify
      ↓
Design
      ↓
Review / Approve
      ↓
Tasks
      ↓
Finalize Task List
      ↓
Implementation
```

### Key Benefit

Specs provide **clear requirements, design planning, tracking, and living documentation**, reducing misunderstandings and rework.

# Agent Steering

**Agent Steering** provides Kiro with **persistent project knowledge** through Markdown files.

Steering files can define:

- Coding standards
- Project conventions
- Architecture decisions
- Project-specific knowledge

This helps Kiro generate code and recommendations that remain consistent with the project.

### Default Steering Files

```text
product.md   → Product vision, features, target users
structure.md → Project structure and organization
tech.md      → Technology stack, tools, frameworks, guidelines
```

### Easy Memory

> **Steering = Tell Kiro how your project works and how code should be written.**

# Autopilot vs Supervised Mode

## Autopilot

Kiro can work autonomously across multiple files and implement related changes without requiring approval for every step.

Useful for:

- Routine tasks
- Well-defined patterns
- Faster development

## Supervised

The developer reviews and approves changes before implementation.

Provides:

- Greater control
- Change review
- Ability to revert changes
- Explicit approval for sensitive operations

```text
Autopilot   → Kiro works more autonomously
Supervised  → Developer reviews changes
```

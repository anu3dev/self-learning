# 1. Amazon VPC

## What is VPC?

**Amazon VPC (Virtual Private Cloud)** is a logically isolated virtual network in AWS where you can launch resources such as:

- EC2
- RDS
- Load Balancers
- NAT Gateways
- Application servers
- Databases

Think of a VPC as your **own private network inside AWS**.

### Important Concept

A VPC is **regional**.

A VPC can span multiple **Availability Zones (AZs)** within an AWS Region.

However:

> **A subnet belongs to exactly one Availability Zone.**

Example:

```text
AWS Region
│
├── Availability Zone A
│   ├── Public Subnet
│   └── Private Subnet
│
├── Availability Zone B
│   ├── Public Subnet
│   └── Private Subnet
│
└── Availability Zone C
    ├── Public Subnet
    └── Private Subnet
````

### Important Correction

A VPC does **NOT automatically create subnets across all AZs**.

You decide:

-  Which AZs to use 
-  How many subnets to create 
-  CIDR ranges for those subnets 
-  Which resources go into each subnet

# 4. CIDR

## What is CIDR?

CIDR stands for:

**Classless Inter-Domain Routing**

Example:

```
```

```
10.0.0.0/24
```

The `/24` indicates how many bits are used for the network portion.

For IPv4:

```
```

```
/24 → 256 total IP addresses
```

Example:

```
```

```
10.0.0.0/24

Network:
10.0.0.0

Usable range:
10.0.0.1 – 10.0.0.254

Broadcast:
10.0.0.255
```

### AWS Important Point

For an AWS subnet, AWS reserves **5 IP addresses** from the subnet.

For example, in:

```
```

```
10.0.0.0/24
```

there are:

```
```

```
256 total addresses
- 5 AWS-reserved addresses
= 251 usable addresses
```

# 5. VPC Route Tables

When a VPC is created, AWS creates a **main route table** for the VPC.

The main route table cannot be deleted while it is the VPC's main route table.

You can also create additional/custom route tables.

## Route Table Purpose

A route table determines:

> **Where network traffic should go.**

Example:

```
```

```
Destination       Target
-----------       ------
10.0.0.0/16      local
0.0.0.0/0        Internet Gateway
```

The `local` route allows communication between resources within the VPC CIDR.

---

# 6. Subnet and Route Table Association

Every subnet is associated with a route table.

If you don't explicitly associate a subnet with a custom route table, it uses the **main route table**.

Therefore:

```
```

```
Subnet
   │
   └── Route Table
          │
          ├── Local route
          ├── Internet Gateway
          └── NAT Gateway
```

---

# 7. Public Subnet

A subnet is considered **public** when its associated route table has a route to an Internet Gateway.

Typical route:

```
```

```
0.0.0.0/0 → Internet Gateway
```

Example:

```
```

```
Internet
   │
   ▼
Internet Gateway
   │
   ▼
Public Subnet
   │
   ▼
EC2
```

For an EC2 instance to be directly reachable from the Internet, it generally also needs:

-  Public IPv4 address / appropriate public connectivity 
-  Security Group allowing the required inbound traffic 
-  Correct routing 

---

# 8. Private Subnet

A private subnet does **not** have a direct route to an Internet Gateway.

Typical architecture:

```
```

```
Internet
   │
   ▼
Internet Gateway
   │
   ▼
Public Subnet
   │
   ▼
NAT Gateway
   │
   ▼
Private Subnet
   │
   ▼
Private EC2
```

### Key Point

A NAT Gateway allows resources in a private subnet to initiate **outbound Internet connections**.

It does **not** make private EC2 instances directly reachable from the Internet.

# 9. Internet Gateway (IGW)

An Internet Gateway provides Internet connectivity between a VPC and the Internet.

Steps:

1.  Create Internet Gateway 
2.  Attach Internet Gateway to VPC 
3.  Create/configure route table 
4.  Add route: 

```
```

```
0.0.0.0/0 → Internet Gateway
```

5.  Associate the route table with the subnet 

This makes the subnet a **public subnet**.

# 10. NAT Gateway

A NAT Gateway allows resources in a private subnet to access the Internet without allowing unsolicited inbound Internet connections.

Example:

```
```

```
Private EC2
    │
    ▼
Private Route Table
    │
    ▼
NAT Gateway
    │
    ▼
Internet Gateway
    │
    ▼
Internet
```

### NAT Gateway is normally placed in:

**Public Subnet**

Why?

Because the NAT Gateway needs a route to the Internet Gateway.

### Certification Memory

```
```

```
IGW → Internet access for public resources

NAT Gateway → Outbound Internet access for private resources

# 11. Security Groups

A Security Group acts as a **virtual firewall** for resources such as EC2.

It controls:

-  Inbound traffic 
-  Outbound traffic 

Example:

```
```

```
Internet
   │
   │ HTTP : 80
   ▼
Security Group
   │
   ▼
EC2
```

Example inbound rules:

| TypePortSource |     |             |
| -------------- | --- | ----------- |
| SSH            | 22  | Your IP     |
| HTTP           | 80  | `0.0.0.0/0` |
| HTTPS          | 443 | `0.0.0.0/0` |

### Important Security Group Characteristics

- **Stateful** 
-  Return traffic is automatically allowed 
-  Rules are allow-based 
-  No explicit deny rule 

### Easy Memory

> **Security Group = Firewall attached to a resource/ENI**

## 13.1 Amazon S3

**Amazon S3 = Object Storage**

Data is stored as objects inside **buckets**.

```
```

```
S3
│
└── Bucket
    ├── Object
    ├── Object
    └── Object
```

Common use cases:

-  Images 
-  Videos 
-  Documents 
-  Backups 
-  Logs 
-  Static websites 
-  Data lakes 

### Important

An S3 bucket is created in a specific AWS Region.

---

## 13.2 S3 Glacier

S3 Glacier refers to S3 storage classes designed for **archive data**.

Examples include:

-  S3 Glacier Instant Retrieval 
-  S3 Glacier Flexible Retrieval 
-  S3 Glacier Deep Archive 

Use Glacier storage classes when data is accessed rarely and you want lower storage costs.

### Important Correction

Modern AWS terminology generally uses **S3 Glacier storage classes**.

The older standalone Glacier service used the concept of **vaults**.

---

## 13.3 Amazon EBS

**EBS = Elastic Block Store**

EBS provides **block storage** for EC2.

Think:

```
```

```

 └── EBS Volume

Use cases:

-  Operating system disk 
-  Application data 
-  Database storage 
-  Persistent EC2 storage

## 13.4 Amazon EFS

**EFS = Elastic File System**

EFS provides managed **file storage** that can be mounted by multiple compute resources.

# 30. Amazon CloudFront

**Amazon CloudFront** is AWS's Content Delivery Network (CDN).

Its primary purpose is:

> **Deliver content from locations closer to users to reduce latency and improve performance.**

CloudFront uses a global network of **Edge Locations**.

Example:

```
```

```
                    Origin
                 S3 / ALB / EC2
                       │
                       ▼
                  CloudFront
                 /    |    \
                /     |     \
               ▼      ▼      ▼
            Edge    Edge    Edge
          Location Location Location
              │       │       │
              ▼       ▼       ▼
           Users    Users    Users
```

---

# 31. CloudFront vs Load Balancer

This is an important interview and certification comparison.

| Load BalancerCloudFront                     |                                     |
| ------------------------------------------- | ----------------------------------- |
| Distributes traffic across backend targets  | Delivers content closer to users    |
| Works primarily as traffic distribution     | Works primarily as CDN              |
| Routes requests to targets                  | Caches/delivers content             |
| Helps distribute application traffic        | Reduces latency and origin requests |
| Can perform health-based routing to targets | Uses Edge Locations                 |

### Easy Memory

> **Load Balancer = Which backend should handle the request?**

> **CloudFront = Can I serve this content closer to the user?**

### Important

CloudFront is **not a replacement for a Load Balancer**.

They are often used together:

```
```

```
User
 │
 ▼
CloudFront
 │
 ▼
ALB
 │
 ▼
EC2 / Application
```
